# Mandarin Roots operations platform

Internal web app for the Mandarin Roots team (part of the Ambro group): **invoicing** with a pixel-matched branded PDF, a **CRM** for visa and Canton Fair leads, and **travel tracking** with document upload and one-click travel pack compilation.

Built with Next.js 15 (App Router, TypeScript, `src/`), Tailwind CSS v4, shadcn/ui, Supabase (Postgres, Auth, Storage), react-hook-form + zod, TanStack Table, Puppeteer (`@sparticuz/chromium`), pdf-lib and sharp. Deploys to Vercel.

## 1. Setup you must run yourself

The Supabase project **mandarin-roots** (`hshvlayauyoqwbbveiqd`, region `ap-southeast-1`) has already been created and migrated and the four team accounts exist. The database holds real data only; no sample records. What remains needs credentials that only you can access:

1. **Get the keys.** Supabase dashboard → Project Settings → API Keys. The `sb_publishable_…` (or legacy anon) key is `NEXT_PUBLIC_SUPABASE_ANON_KEY`; the `sb_secret_…` (or legacy service_role) key is `SUPABASE_SERVICE_ROLE_KEY`. Never commit the secret one.
2. **Rotate passwords and enable MFA** on the Supabase project. See `SECURITY.md`.
3. **Vercel:** import the GitHub repo, add the environment variables below as Config (public ones) and Secret (service key), and redeploy. Do not set `PUPPETEER_EXECUTABLE_PATH` on Vercel. Chromium for PDF generation needs the Node.js runtime with at least 1024 MB memory (the Vercel default) and `maxDuration = 60`, which the API routes already declare. Check `https://<your-app>/api/health` after deploying; it reports whether the variables reached the server without revealing them.

### Environment variables

Copy `.env.example` to `.env.local` locally, and add the same keys in Vercel → Project → Settings → Environment Variables:

| Variable | Where it is used |

## 2. Local development

```bash
npm install
cp .env.example .env.local   # fill in the values
npm run dev                  # http://localhost:3000
```

Useful scripts:

| Command | What it does |
|---|---|
| `npm run build` | Production build (also typechecks and lints) |
| `npx tsc --noEmit` / `npm run lint` | Typecheck / lint |
| `npx tsx scripts/seed-users.ts` | Create or update the four accounts via the Admin API (needs the service role key) |
| `PUPPETEER_EXECUTABLE_PATH=... npx tsx scripts/check-invoice-pdf.ts` | Golden check: renders MR-2026-179, asserts one A4 page and the amount-in-words rules, writes `tmp/invoice-check.pdf` and `.png` |
| `PUPPETEER_EXECUTABLE_PATH=... npx tsx scripts/check-travel-pack.ts` | Builds a travel pack from sample files, asserts page count, A4 sizes and metadata |

Database changes live in `supabase/migrations/` (numbered SQL files, already applied to the project). Regenerate types after a migration: Supabase dashboard → API Docs → TypeScript, or `supabase gen types typescript --project-id hshvlayauyoqwbbveiqd > src/types/database.ts`.

## 3. Modules

**Invoicing** (`/invoices`): live A4 preview while typing, quick-add lines, drag-to-reorder, amount in words for USD / AED / CNY / INR, numbering `MR-{year}-{n}` claimed atomically on save (counter seeded at 178, so the first real invoice is MR-2026-179), PDF generated by Puppeteer on first download and stored in the private `invoices` bucket, then re-served from storage. Cancelled invoices are kept so the sequence has no gaps.

**CRM** (`/leads`): one-screen lead entry (name, phone, enquiry type required; E.164 phone with country code), kanban with optimistic drag and a lost-reason dialog, table view, lead detail with editable fields, activity timeline, linked invoices and travellers, "Create invoice" and "Mark won → Add to travel". Follow-ups at `/leads/followups` grouped Overdue / Today / This week with one-click snooze.

**Travel** (`/travel`): groups with a travel window and code (`G01`…`Gn`, bulk create, reference prefix such as `MR144`), traveller records with a searchable group picker that also sets the traveller's dates, four required document slots plus "Other" (PDF/JPG/PNG/HEIC, 15 MB, HEIC converted server-side, multi-file drop with filename auto-assign), status auto-advances to Documents Complete, one-click **Compile travel pack** per traveller (branded cover, images fitted to A4, merged with pdf-lib, metadata title, stored with history), and **Compile group PDF**: one merged file per group, group cover then every traveller's PAR, passport, flight ticket and hotel booking in order, named `MR144-Aug25-Aug30-05px-G01.pdf` (prefix, start, end, pax count, group code). Also a by-traveller table and a month calendar.

**Dashboard** (`/`): leads this month, conversion rate, USD invoiced this month, travellers in the next 7 days, follow-ups due, travellers with incomplete documents travelling within 7 days, recent invoices, leads by enquiry type.

## 4. Decisions and deviations from the brief

- **Invoice typography matches the reference PDF, not the brief.** The reference invoice (`MR-2026-179`) is set in Carlito (Calibri-compatible) with Noto Sans CJK, and every measurement in the brief is scaled by about 0.77 in the actual file. The template uses the measured values (Carlito embedded from `public/fonts`, a Noto Sans SC subset for the address, Google's Noto Sans SC as fallback for other CJK text). Result: one A4 page, all text positions within 1 pt of the reference. Poppins and Inter are used for the app UI as specified.
- **Table headers on the invoice are left-aligned** (QTY, RATE, AMOUNT) while values are right-aligned, and the signature sits at the left of the right-hand footer column, because that is what the reference does.
- **Uploads go straight from the browser to Supabase Storage** (with the user's session and RLS on `storage.objects`) and are then registered through a server action. Vercel serverless functions cap request bodies at 4.5 MB, so a 15 MB file cannot pass through a route handler.
- **Extra columns:** `leads.entry_city` (intended entry city for visa enquiries; `travel_month` holds the travel window), `traveller_documents.deleted_at` / `deleted_by` (soft delete for the audit trail), `travel_groups.travel_end_date` and `travel_groups.reference_prefix` (group window and PDF naming), and a `traveller_2026` counter. Everything else follows the brief's schema.
- **Atomic numbering:** `create_invoice`, `update_invoice`, `create_lead` and `create_traveller` Postgres functions claim the counter and insert in one transaction.
- **PDF thumbnails** in the document slots show a PDF icon rather than a rendered first page; image uploads show real thumbnails via signed URLs.
- **Conversion rate** is defined as won ÷ (won + lost) over the last 90 days. "Invoiced this month" sums USD invoices only (other currencies are excluded rather than converted).
- **Company phone** on the invoice is `+8519597408840`, copied from the reference PDF. Edit `COMPANY` in `src/lib/constants.ts` if that is wrong.
- **Vercel Hobby limits:** route handlers run for at most 60 seconds. Compiling a whole group's packs launches one Chromium and renders one cover per traveller; groups larger than roughly 15 travellers with heavy scans may need the Pro plan (300 s) or per-traveller compilation.
